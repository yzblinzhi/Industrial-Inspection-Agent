### 5.4 app/graph/ —— LangGraph 编排层（业务核心）

**流转总图**（当前版本：结论二态 pass|fail，复核走"申请→工作台"，无图内 interrupt）：

```
START → input_parser
  ├─(need_guidance: 缺工件号/未登记且无法纠正)→ END（只回填报指引，不落库）
  ├─(request_review)→ review_request → END
  ├─(new_inspection: 有图+已登记工件号)→ cv_engine → standard_validator
  │      ├─(validator_notice: 无标准/低置信度，已保守判不合格)→ report_generator
  │      ├─(有超标项/可疑项)→ rag_retrieval → reasoning → self_reflection
  │      │      └─(不过且 retries<2)→ reasoning（循环，上限 2 次）
  │      └─(全部合格)→ reasoning
  │      reasoning → self_reflection →(过/超限)→ report_generator → END
  └─(其他)→ qa_answer → END
```

| 文件 | 职责与关键点 |
| --- | --- |
| `state.py` | `AgentState(TypedDict)`：`messages` 用 `add_messages` reducer（多轮上下文，Checkpointer 自动持久化）；业务字段为"最近一次检测快照"；`status` 单枚举（pass/fail 二态 + pending/rechecking 过程态）；`validator_notice`（比对阶段给用户的提示）；**State 不携带图片 base64**，只传 `image_key` |
| `edges.py` | 全部条件路由：`route_after_parse`（inspect/qa/review/finish 四向；**inspect 必须有图+已登记工件号**）、`route_after_validate`（notice→report 直出 / 超标或可疑→retrieval / 合格→reason）、`route_after_reflection`（自检不过→regen 循环） |
| `builder.py` | `build_graph(checkpointer)`：注册 9 节点 + 条件边 + 编译。改流转只动这里和 edges.py |

**nodes/（一文件一节点）**：

| 节点文件 | 职责 | 输入 → 输出（State 键） | 调试要点 |
| --- | --- | --- | --- |
| `input_parser.py` | 意图识别（LLM 结构化 `IntentParse`，失败降级规则）；**工件三级解析**：精确工件号 → 名称匹配（`base_name` 去尾代号后 in text）→ 编号相似度 ≥0.8 笔误纠正（difflib）；解析失败 → `need_guidance` + 填报指引消息，**直接 END 不落库** | `user_input` → `intent/workpiece_info`(+guidance 消息) | `_resolve_workpiece()` 纯函数可独立调试；关键词表 INSPECT/HISTORY/REVIEW_KW 在文件头 |
| `cv_engine.py` | 调 CVProvider；**检测单据在此创建**（工件号已过登记校验，杜绝 UNKNOWN 脏单） | → `cv_result`, `status=detecting` | 契约校验失败会抛错 → SSE error 事件 |
| `standard_validator.py` | 读 PG `quality_standards` → `compute_gaps` 纯函数比对（面积/长度/ΔE/数量/置信度五类判据）；**无标准+有检出 → fail + notice**（按不合格保守处理）；**低置信度 → fail + notice** | → `standard_gaps/suspects/status/validator_notice` | `compute_gaps` 不依赖 DB，单测覆盖（tests/test_standards） |
| `rag_retrieval.py` | 按超标/可疑类型拼查询 → RAGProvider → `rag_docs`（含 params）+ `rag_context` | → `rag_docs/rag_context` | 检索失败不阻断（docs=[] 继续） |
| `reasoning.py` | LLM 结构化 `ReasoningReport`（conclusion/root_cause/suggestions/summary_text）；失败重试 2 次；**超限/鉴权异常 → 保守判 fail**；facts 以 `<facts>` JSON 注入 Prompt | → `analysis_report`(+status) | Prompt 在 `app/prompts/reasoning.py`（含"禁止 JSON 字段名"约束）；LLMAuthError 直接抛给对话 |
| `self_reflection.py` | **防幻觉硬规则**（核心）：R1 结论一致性 / R2 建议缺陷⊆超标项 / R3 参数值在 RAG 范围表或与文档正文一致 / R4 结论文本数值可溯源（白名单含检出数、类型数、模型名、图像尺寸、meta、批次号；5% 容差）/ R5 根因禁模糊词。失败回流 reasoning（上限 2 次），**超限强制 fail** | → `reflection_ok/retries/errors`(+status) | `run_hard_rules` 纯函数、不依赖 LLM，单测覆盖（tests/test_reflection） |
| `report_generator.py` | 收口节点：①补齐 pass/保守 fail 的最小报告；②自检强制 fail 时纠正结论标记；③Markdown 报告 → MinIO（失败不阻断）；④`save_result` 落库（回填工件号/批次）；⑤展示消息追加（含 validator_notice、自检警示） | → `analysis_report/report_file_key/status/messages/last_inspection_id` | 报告模板 `render_report_markdown()` 五节结构 |
| `review_request.py` | 对话申请复核：定位本人记录（last_inspection_id 优先，否则按工件号最近一条）→ 置 need_review → 回执消息 | → `messages` | 定位/幂等逻辑在 `services/inspection.request_review` |
| `qa_answer.py` | 无图会话问答/历史查询：最近检测快照 + RAG 文档作上下文；**操作工角色剔除参数**（角色裁剪）；LLM 失败有兜底文案 | → `messages` | Prompt 在 `app/prompts/qa.py`（规则 2 是角色裁剪） |

### 7.4 已知坑（改代码前先看）

1. **异步应用必须用 `AsyncRedisSaver`**（同步版无 astream 所需方法，报 NotImplementedError）。
2. **RediSearch 只能 DB0 建索引**——Checkpointer 别放 DB1。
3. ORM 时间列必须 `DateTime(timezone=True)`，混 naive/aware 写库必炸。
4. `alembic.ini` 与含中文注释的 ini 在 Windows GBK 下会 UnicodeDecodeError。
5. passlib 需锁 `bcrypt<4.1`（已在 pyproject 锁定）。
6. LLM 401/403 已快速失败并透传对话——见到即查 key 与 `QWEN_BASE_URL` 匹配性，勿加重试。
7. 评测/冒烟断言按 **Mock LLM** 校准；qwen 模式请加 `LLM_PROVIDER=mock` 前缀跑回归。
8. Vite 热更新偶发不生效（短时间多次编辑同一文件）：重启 `npm run dev`，必要时 `--force`。

## 九、检测数据库（去重视图）

- 端点：`GET /api/v1/inspections/database`（`services/inspection.py::database_view`）；
- 去重键：`工件号 + 批次号`（空批次归"未分批"组），同键取最新一次（DISTINCT ON + id DESC），附检测次数与工件名；
- 批次号策略：检测时**可选**——用户没说批次不阻断检测，存 null 归未分批；
- 前端页面 `views/DatabaseView.vue`（导航「📦 检测数据库」，三角色可见，操作工字段裁剪）；详情弹窗含该键全部检测时间线（复用 `GET /inspections?workpiece_no=&batch_no=`）。
