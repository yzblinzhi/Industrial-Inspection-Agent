# V1.0 后续对接需求清单

## 一、检测仪器接口输入输出要求

### （一）我方推送输入

我方从MinIO提取原图后，直接向仪器接口推送图片，接口要求如下：

- 协议：HTTP/HTTPS POST，`multipart/form-data` 格式
- 参数字段：

| 字段名       | 类型   | 必填 | 说明                                |
| ------------ | ------ | ---- | ----------------------------------- |
| image        | file   | 是   | 工件原图二进制文件，支持JPG/PNG格式 |
| workpiece_no | string | 否   | 工件型号编号，用于匹配检测模型      |
| request_id   | string | 否   | 请求唯一标识，用于排障追踪          |

### （二）仪器返回输出

返回标准JSON格式，字段要求如下：

```
{
  "model": "检测模型/仪器版本号",
  "image_size": {"width": 像素宽度, "height": 像素高度},
  "detections": [
    {
      "defect_type": "缺陷类型名称",
      "confidence": 置信度数值,
      "bbox_xyxy": [x1, y1, x2, y2],
      "measure": {"area_cm2": 缺陷面积, "max_length_mm": 最大长度}
    }
  ],
  "meta": {"inference_ms": 检测耗时}
}
```

- 说明：`defect_type` 不做固定枚举限制，仪器返回的所有缺陷类型我方均可兼容，后续新增/修改缺陷类型无需调整接口，我方通过代码适配。
- 强制要求：`bbox_xyxy`为原图像素坐标、`measure`为量化物理值（单位cm²/mm），用于标准判定与前端叠框展示。

## 二、RAG 知识库建设需求

1. **需甲方提供**：对应所有缺陷类型的正式喷涂工艺文档，统一使用Markdown格式。
2. **文档格式要求**：每份文档开头包含以下信息头，正文为缺陷定义、根因、整改措施、参数范围等工艺内容。

```
---
doc_id: 文档唯一编号
title: 文档标题
defect_keywords: ["缺陷名称1", "缺陷别名"]
params: 
  参数名: [最小值, 最大值]
version: 版本号
---
正文内容
```

1. 补充说明

   ：

   - 知识库覆盖的缺陷类型可多于当前仪器支持的类型，不会干扰检索效果，后续仪器新增缺陷可直接复用已有文档。
   - 文档分块、向量化、索引构建由我方代码统一处理，甲方仅需提供符合格式的Markdown源文件。

## 三、需求说明

当前V1.0版本已基于前期语言沟通完成开发，跑通了从图片上传、缺陷检测、标准比对、根因分析到报告生成的全业务闭环（当前为Mock模拟数据验证）。 为推进真实检测仪器接入、正式工艺知识库落地，需提供上述接口详细资料、正式工艺文档及配套的工件质检标准阈值，同时还希望能够获得智能体功能需求详细说明，后续将根据要求推动开发。
